# Migration plan

Generated by `bin/migrate`. Mark tasks `[x]` done, `[~]` in progress with a note of what remains.
Track with `bin/progress` (or `bin/progress --todo`).

**Rules:** the old Mac stays untouched until the last phase · verify every copy · secrets never enter git ·
one change at a time on the new Mac.

Selections: transport=cable, secrets=manager, dotfiles=existing, shell=zsh, packages=brew,mas, languages=node,php,python,ruby,rust,go,java, php_stack=herd, containers=docker, editors=jetbrains,vscode,cursor,zed,sublime,xcode, terminal=iterm,ghostty,warp,appleterminal,other_term, ai=claude,codex,gemini,copilot,cursor_ai,other_ai, ai_extras=mcp,skills,profiles,memory, dbtools=client,localdb, browsers=chromium,safari,firefox, apps=launcher,screenshot,windows,notes,ownapps, data=code,documents,pictures,downloads,movies,music,desktop, managed=yes

## Phase 1 — Preparation (old Mac)

- [ ] 1.1 Decide the migration window and keep the old Mac untouched until the end
- [ ] 1.2 Create the new Mac's first account with the **same short username** as the old one (absolute paths in configs keep working)
- [ ] 1.3 Note the macOS versions of both Macs; some settings exports are version-sensitive
- [ ] 1.4 Check with IT what may be copied from/to a managed Mac, and whether Remote Login may be enabled
- [ ] 1.5 Run `bin/inventory` and read the report: it lists what exists only on this machine
- [ ] 1.6 Run `bin/repo-report` and decide per project: transfer, re-clone, archive or drop
- [ ] 1.7 Run `bin/ssh-audit` and decide which keys to keep
- [ ] 1.8 List every paid app and where its licence lives (account / key / device-bound)

## Phase 2 — Capture (old Mac)

- [ ] 2.1 Move shell config into it and symlink it back (`bin/link --apply`), then open a new terminal and verify
- [ ] 2.2 Add app configs that are plain files (editor settings, terminal config, git config, global gitignore)
- [ ] 2.3 Capture macOS defaults into `macos/defaults.sh` (Dock, Finder, keyboard, trackpad, shortcuts)
- [ ] 2.4 Scan the repo history for secrets before pushing it
- [ ] 2.5 Push the repo and confirm it clones on another machine
- [ ] 2.6 Confirm you can sign in to the password manager on another device (recovery kit/secret key available)
- [ ] 2.7 Import the SSH keys you keep into the manager and enable its SSH agent
- [ ] 2.8 Put shell secrets (`export *_API_KEY=...`) into the manager and replace them with a rendered template
- [ ] 2.9 Store project `.env` files and package-registry credentials as documents
- [ ] 2.10 Store export-file passphrases (database client, launcher backup) in the manager
- [ ] 2.11 Collect licence keys into your password manager (or a safe note)
- [ ] 2.12 Deactivate device-bound licences on the old Mac
- [ ] 2.13 Request any company-provided licence keys you don't hold yourself (these can take days)
- [ ] 2.14 Database client: export connections **with passwords**, store the passphrase safely
- [ ] 2.15 Launcher: export settings to a file, store its password safely
- [ ] 2.16 Browsers: note profiles, which spaces/windows belong to which profile, and extensions per profile; export bookmarks as HTML
- [ ] 2.17 JetBrains: push settings sync from the old Mac, and take a local settings backup as an escape hatch
- [ ] 2.18 Screenshot/window/keyboard tools: `defaults export` their preference domains into your dotfiles
- [ ] 2.19 Terminal: point it at a settings folder in your dotfiles (quit it first, set it from another terminal)
- [ ] 2.20 Push everything that can be pushed; note repos with no remote
- [ ] 2.21 Archive stale projects that hold unique work (`tar -czf`, excluding dependency folders)
- [ ] 2.22 Decide the folder layout on the new Mac; if it changes, list what stores absolute paths
- [ ] 2.23 Decide per project: re-seed the local database or move its data

## Phase 3 — Transfer

- [ ] 3.1 Connect the Macs with a USB-C/Thunderbolt **data** cable
- [ ] 3.2 Enable Remote Login on the destination Mac, restricted to your user
- [ ] 3.3 Create a temporary SSH key and authorize it for the cable network only (`from="169.254.0.0/16"`)
- [ ] 3.4 Verify the link: `ping` the address and open an SSH session
- [ ] 3.5 Projects, excluding dependency and build folders (anchor excludes to the transfer root)
- [ ] 3.6 Documents
- [ ] 3.7 Pictures
- [ ] 3.8 Downloads
- [ ] 3.9 Movies
- [ ] 3.10 Music
- [ ] 3.11 Desktop
- [ ] 3.12 Shell history (merge, don't overwrite the new Mac's)
- [ ] 3.13 AI assistant memory/history folders
- [ ] 3.14 App export files and any `.env` files that travel separately
- [ ] 3.15 Verify every copy with `bin/verify-copy` (files and, for projects, git state)

## Phase 4 — New Mac

- [ ] 4.1 Run Setup Assistant **without** Migration Assistant; enable FileVault
- [ ] 4.2 `xcode-select --install`
- [ ] 4.3 Install and sign in to your password manager; enable its SSH agent
- [ ] 4.4 Verify git access: `ssh -T git@github.com` (and any other host you use)
- [ ] 4.5 Clone your dotfiles repo and run its install script
- [ ] 4.6 Install Homebrew and run `brew bundle`; adopt hand-installed apps with `--adopt` where it complains
- [ ] 4.7 Sign in to the App Store, then install App Store apps
- [ ] 4.8 `brew bundle check` reports everything satisfied
- [ ] 4.9 Node: install the version manager and one default version, then global packages
- [ ] 4.10 Python: version manager and `pipx` apps
- [ ] 4.11 Ruby: version manager and the versions you actually need
- [ ] 4.12 Rust: `rustup default stable`, then `cargo install` your tools
- [ ] 4.13 Go toolchain
- [ ] 4.14 JVM toolchain
- [ ] 4.15 Restore package-registry credentials before installing private packages
- [ ] 4.16 Install the PHP environment tool and open it once so its CLI exists
- [ ] 4.17 Install **every** PHP version your sites use, and set the same default version as the old Mac
- [ ] 4.18 Restore parked folders, linked sites, per-site PHP versions and HTTPS
- [ ] 4.19 Restore `php.ini` overrides per version
- [ ] 4.20 Run `composer install` per project using the tool's wrapper, then open one site per project
- [ ] 4.21 Install Docker Desktop (or your alternative) and `docker login` to your registries
- [ ] 4.22 Restore or re-seed local databases; move named volumes only where the data matters
- [ ] 4.23 Start one project's stack end to end as a check

## Phase 5 — Apps

- [ ] 5.1 JetBrains: install, sign in, then **get** settings from your account (never push the fresh install's defaults)
- [ ] 5.2 Re-enter database connection passwords (they live in the Keychain, not in sync)
- [ ] 5.3 VS Code: enable Settings Sync and let extensions finish installing
- [ ] 5.4 Cursor: sign in, restore settings, rules and MCP config
- [ ] 5.5 Zed: confirm settings, keymap and snippets from your dotfiles
- [ ] 5.6 Sublime Text: restore packages and settings
- [ ] 5.7 Xcode: install, open once, accept the licence, install additional components
- [ ] 5.8 iTerm2: load settings from your dotfiles folder, then set saving to automatic
- [ ] 5.9 Ghostty: config from dotfiles
- [ ] 5.10 Warp: sign in
- [ ] 5.11 Apple Terminal: import your profile
- [ ] 5.12 Open a new terminal and verify prompt, PATH, aliases and your shell functions
- [ ] 5.13 Install the CLIs you use and log in to each (auth files are per-device; don't copy them)
- [ ] 5.14 Link your shared instructions file into each tool
- [ ] 5.15 Render your MCP server definitions into each tool, with secrets as `${VAR}` references
- [ ] 5.16 Restore your own skills from your dotfiles; re-install third-party ones from source
- [ ] 5.17 Repeat per profile; start each profile once before writing its config
- [ ] 5.18 Put memory/history folders in place and rename any keyed by a project path that changed
- [ ] 5.19 Copilot: sign in per IDE
- [ ] 5.20 Verify: instructions load, MCP servers connect, skills are listed
- [ ] 5.21 Install the client, activate its licence, import the connections export
- [ ] 5.22 Open one connection that uses an SSH tunnel to confirm key access
- [ ] 5.23 Confirm local databases exist and apps can reach them
- [ ] 5.24 Sign in and let sync restore what it can
- [ ] 5.25 Re-create profiles and re-assign spaces/windows to them
- [ ] 5.26 Verify bookmarks and pinned tabs; import your HTML export where anything is missing
- [ ] 5.27 Re-install extensions per profile
- [ ] 5.28 Sign in to sites again (sessions and cookies never migrate)
- [ ] 5.29 Launcher: import its settings export, grant Accessibility
- [ ] 5.30 Screenshot tool: `defaults import` **before** first launch, activate licence, grant Screen Recording
- [ ] 5.31 Window manager: restore preferences, grant Accessibility
- [ ] 5.32 Note app: point it at the copied folder
- [ ] 5.33 Grant privacy permissions for everything else that asks
- [ ] 5.34 Sign in to the remaining apps you use daily
- [ ] 5.35 Build your own apps from source (use the project's build script, not just the plain build command)
- [ ] 5.36 Recreate any `~/Applications` symlinks, and check anything that launches them by absolute path
- [ ] 5.37 Run your `macos/defaults.sh`, then log out and back in
- [ ] 5.38 Modifier remapping (e.g. Caps Lock): set it for the keyboards present on this Mac
- [ ] 5.39 Import keyboard shortcuts, and re-check anything the apps above claimed

## Phase 6 — Verification

- [ ] 6.1 Tests pass in 2–3 projects, using the right runtime versions
- [ ] 6.2 `git push` works from a real repo
- [ ] 6.3 Every copied folder verified (files and sizes)
- [ ] 6.4 Dotfiles: linking reports nothing pending; the repo is clean after a day's use
- [ ] 6.5 Remove the temporary transfer key from both Macs and turn Remote Login off

## Phase 7 — Decommission (2+ weeks later)

- [ ] 7.1 Final sweep of the old Mac for anything created or changed since the transfer
- [ ] 7.2 Deactivate remaining licences and sign out of accounts (Apple Account, password manager, browsers)
- [ ] 7.3 Confirm 2FA codes and passkeys are available on another device
- [ ] 7.4 Wipe the old Mac (or hand it to IT following their process)
- [ ] 7.5 Keep the dotfiles repo, the archives and the export files for next time
